# 02 — Content Audit: KEEP / MODIFY / MERGE / MOVE / REMOVE

*Component IDs refer to `01-current-state-map.md`. Page references are printed page numbers.*

## Classification rules applied

| Code | Meaning in this audit |
|---|---|
| **KEEP** | Effective and well positioned. Carry forward substantially as is (copy-editing allowed). |
| **MODIFY** | Valuable, but needs simplification, a stronger application step, or explicit links to the rest of the system. |
| **MERGE** | Substantially overlaps another component. Combine them, keeping the best of each. |
| **MOVE** | Useful, but badly positioned in the development journey. |
| **REMOVE** | Contributes too little to LO 1.1–1.3 to justify its space. |

Where two codes apply (e.g. MOVE + MODIFY), the **primary** code comes first.

**Protected content.** Doctrinal and mandated material is never classified REMOVE. That covers the leadership definitions, the Leadership Framework (Tōtara tree, Key Elements, Essential Tasks, Behaviour Statements), the Value Adds, Mission/Vision/Ethos/Values and te reo. Any recommendation to change that material concerns **presentation or position only**, never wording.

**On repetition.** For each repeated element the audit asks whether the repetition is **deliberate reinforcement** (the same thing revisited later to show change) or **unnecessary duplication** (the same thing restated with nothing new asked). The verdict is given in the reasoning.

## Reflection group — the 22 Lesson Reflection pages

Components C7, D4, E4, F3, G3, H6, I2, J3, K5, L3, M5.

**Code: MERGE + MODIFY.**

**What they are.** Every topic chapter ends with two identical pages ("Lesson Reflection – X 1" and "X 2"). Each rates five Behaviour Statements as Strength or Development Area, then runs Keep/Stop/Start on one development area and names situations to use it.

**Is the twin page deliberate reinforcement?** Probably intended as such (a second rating later in the course), but **nothing in the workbook says when or why to complete page 2**. Without that instruction it functions as duplication. Either the second page is a re-rating at a defined later point, or it is a spare.

**Is the cross-chapter repetition deliberate?** The *mechanism* repeats 11 times. Some repetition of a familiar routine helps an 18-year-old: they learn the drill once. But:

- The same Keep/Stop/Start is asked up to **27 times**. Recruits will generate 11+ development areas, each with a strategy, and **none is ever carried forward**. The LDP draws only on post-exercise feedback.
- Rating a behaviour as "Strength / Development Area" in a lesson, before it has been tested, is largely speculative. The workbook itself acknowledges this ("keep in mind you are in the orientation phase").
- Asking for a new development area in every lesson dilutes focus. The LDP itself asks for **one priority strength and one priority development area**, not eleven.

**Recommendation.**

1. **Collapse each twin pair into one page.** If re-rating is intended, give the page two dated columns (lesson / later), so the change is visible.
2. **Differentiate the chapter reflection from the LDP.** Lesson-level reflection should be light: *which one statement will I try this week, and where?* Keep/Stop/Start is kept for the LDP, where it earns its place.
3. **Carry forward.** Each chapter's one chosen statement feeds a single running *development record* (doc 06), which feeds the LDP.
4. **Tag each topic to its Value Add** so recruits are not left to map this alone at planning time.

This removes about 11–16 pages without removing a single doctrinal element or learning activity.
